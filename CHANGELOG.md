# Changelog

## [0.4.0] - 2026-11-15
- New: voice commands. Hold Shift with the microphone key (or with a Fn hold or double-tap) and say what you want done; Glossa sends the transcript, the frontmost app's window title, the last 30 lines on screen and this Mac's host, user and shell to a chat model, and pastes the one command it answers with, without Return. If it can't write a sensible command it asks a short question instead, and risky commands (rm -rf, sudo, disk tools, force-push, reset --hard, kill) come with a warning. Both show in a notice at the top of the screen, which also shows the answer as it streams. Same prompt and contract as Smart Terminal's voice commands.
- Setup notes: `~/.config/glossa/setup.txt` (*Edit Setup Notes…* in the menu) goes with every voice command, so commands can use your own hosts, ssh aliases, folders and shell helpers. A request that names another machine from the notes is written as `ssh <host> '…'`.
- Config: `assistEndpoint`, `assistApiKey`, `assistModel` (default `code`). With an llm-router or LiteLLM `endpoint`, the chat URL and key are derived from it; a transcription-only key needs `assistApiKey`.
- New sounds: a family of short synthesized notes replaces the system alerts (Pop, Tink, Morse, Purr, Basso). Notes rise on start and fall on stop, dictation sounds soft and voice commands bright, and each outcome has its own: text inserted, command pasted, command worth checking, question from the model, too short or silent, failed. Press-and-hold starts with a single note; stopping now has a sound too.
- New: *Type While Speaking* (menu, off by default). Dictation appears while you talk: every `liveInterval` seconds (0.8) the audio so far is transcribed and the typed text follows, deleting only what changed and typing the new ending; words two passes agree on stay. Finished sentences (closed with . ? or ! and followed by more speech) are locked: never retyped, and later passes, the final one included, send only the audio after them, using the segment timestamps from `verbose_json`. Whisper often keeps several sentences in one segment, so sentences lock by text and the audio window moves on at a segment boundary, or, once a window passes 20 s, at an estimate (with the repeated words at the seam dropped), keeping every window well under Whisper's 30 s. Locked sentences are found in each new pass by content, not by count. Only the text before the window goes into Whisper's prompt. Pauses send nothing, and trailing silence is trimmed from each pass, so Whisper doesn't repeat the last phrase. A rate limit from the server (HTTP 429) pauses live passes for 15 s.
- Fixed: a phrase Whisper repeats back to back ("All right. All right. All right. …"), typically on the last fraction of a recording just over 30 s, is kept once: any run of 2 to 8 words three times or more, or one word four times or more. Clicking elsewhere or pressing a key freezes editing for that recording, and the full text goes to the clipboard. Typed as key events, so the clipboard isn't touched while you talk.
- Fixed: a microphone chosen in the menu recorded nothing ("0.0s, -120 dBFS") when it wasn't also the output device. Recording now uses an AudioQueue, which records from any device and resamples to 16 kHz itself.
- New: a *Microphone* menu lists every input device plus *System Default*; the choice is remembered, and a chosen mic that isn't connected falls back to the default (said in the menu and the log).
- Fixed: after the input device changed (AirPods, a dock or display mic), recordings could come back as silence, which Whisper answered with the glossary in a loop ("Ploi, DigitalOcean, Xcode, Xcode, …"). Each recording now opens the current device; a recording that stays silent (below `silenceDB`, default -80 dBFS) is not sent, and a notice names the device. Transcripts stuck in a loop or only echoing the glossary are dropped.
- Fixed: Whisper sometimes ended a transcript with a subtitle credit it never heard ("Closed Captioning by …", "Thanks for watching", "Subtitles by the Amara.org community"), learned from subtitled video and triggered by the silence before you press stop. The quiet tail of a recording is now cut half a second after the last sound before it is sent, and those credit lines are dropped from the end of a transcript (the log names what was dropped).
- Menu: *Start Voice Command*. The menu-bar icon is a red terminal while recording a command.

## [0.3.0] - 2026-11-12
- New: a fallback server. `fallbackEndpoint` (with `fallbackApiKey` and `fallbackModel`) names a second server that takes the recording when `endpoint` fails for any reason: no network, the laptop off the tailnet, the server down, a bad key. With a fallback set, the primary gets `primaryTimeout` seconds (default 10) of silence before the same audio goes to the fallback. The menu shows both servers and which one answered last, and *Use Fallback Server* sends everything to the fallback until unchecked. The typical pair is a GPU box as `endpoint` and the local whisper-server as the fallback.
- Fixed: a plain `http://` endpoint on another machine (a Whisper server on your LAN or tailnet, llm-router, Speaches) failed every transcription with "App Transport Security policy requires the use of a secure connection", and the error sound played after each recording. Only 127.0.0.1 was exempt. The app now allows those connections; `https://` endpoints are unaffected.
- Changed: the glossary seeded on first launch is a generic developer vocabulary (kubectl, PostgreSQL, Next.js, pnpm…) instead of the author's hostnames. Existing `glossary.txt` files are untouched.
- The log line for each transcription now names the server that answered.

## [0.2.0] - 2026-11-03
- New: music ducks while you dictate. If something is playing on the output device when recording starts, Glossa lowers the system volume by `duckPercent` points (default 10) and restores it when recording stops, unless you moved the volume in the meantime. `duckOnlyIfPlaying: false` ducks always; `duckPercent: 0` disables it.
- New: Homebrew. `brew install --cask pluginslab/tap/glossa` installs the app and whisper-cpp, and links `glossa-server`, which sets up the local Whisper launch agent. The same script now ships inside the app at `Glossa.app/Contents/Resources/install-server.sh` for DMG users.

## [0.1.0] - 2026-11-03
- First release. A menu-bar app that takes over the Mac's dictation key and sends what you say to a Whisper server, with a glossary and the text before your cursor as the prompt, so technical terms come out spelled right.
- Triggers: the microphone key (F5) to start and stop, or hold it for push-to-talk; Fn double-tap or hold as an alternative. The mic key press is swallowed before macOS sees it, so Apple's "enable Dictation?" dialog never appears.
- Prompting: `~/.config/glossa/glossary.txt` (one term per line) plus, where the app exposes it through Accessibility, up to 300 characters before the insertion point. The glossary goes first and the context last, so the context survives Whisper's prompt limit.
- Insertion through the pasteboard and a synthetic ⌘V, with the previous pasteboard contents restored afterwards. A leading space is added when the character before the cursor is not whitespace.
- Any OpenAI-style `/v1/audio/transcriptions` endpoint works: the local whisper.cpp `whisper-server` by default (`scripts/install-server.sh` sets it up as a launch agent), or a LiteLLM / Speaches / faster-whisper server over the network with `endpoint`, `apiKey` and `model` in `config.json`.
- `language` defaults to `en`; auto-detection works but costs about half a second per request. Recordings under 0.4 s are dropped. Start, done and error sounds. Everything is logged to `~/Library/Logs/glossa.log`, including round-trip times.
